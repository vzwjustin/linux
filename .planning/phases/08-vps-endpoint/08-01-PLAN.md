Create net/tquic/tquic_server.c with multi-tenant connection tracking:

1. Define `struct tquic_client` to track per-router state:
   - psk_identity (string, up to 64 bytes)
   - psk (32 bytes for TLS 1.3 PSK)
   - port_range_start, port_range_end (u16)
   - bandwidth_limit (u64, bytes/sec)
   - connection_count (atomic_t)
   - stats: tx_bytes, rx_bytes, active_paths
   - traffic_class_weights[4] (for QoS)
   - conn_rate_limit (u32, connections per second, default 10)
   - rate_tokens (atomic_t, current token bucket level)
   - rate_last_refill (ktime_t, last token refill time)

2. Create rhashtable for client lookup by PSK identity:
   - `tquic_client_table` with string key (psk_identity)
   - `tquic_client_lookup_by_psk()` for handshake callback
   - `tquic_client_register()` and `tquic_client_unregister()`

3. Implement token bucket rate limiting:
   - `tquic_client_rate_limit_check(client)`: Returns true if connection allowed
   - Refill tokens based on elapsed time since rate_last_refill
   - Max bucket size = conn_rate_limit (1 second of burst)
   - On check: refill, then decrement if tokens > 0, else reject
   - Log rate limit hits (ratelimited)

4. Extend `struct tquic_connection` in include/net/tquic.h:
   - Add `struct tquic_client *client` pointer
   - Add `enum tquic_conn_role { TQUIC_ROLE_CLIENT, TQUIC_ROLE_SERVER }` field

5. Implement connection-client binding:
   - `tquic_server_bind_client()` called after successful PSK auth AND rate check
   - Increment client connection_count
   - Decrement on connection close

Per CONTEXT.md: Auto-accept on valid PSK, resource-based limits only.

  <files>net/tquic/tquic_handshake.c, net/tquic/tquic_socket.c, include/uapi/linux/tquic.h</files>
  <action>
Integrate PSK identity into TLS handshake with rate limit enforcement:

1. Add SO_TQUIC_PSK_IDENTITY sockopt to include/uapi/linux/tquic.h:
   - Value: next available sockopt number after existing ones
   - Used to set PSK identity for outbound connections (client mode)
   - Used to configure PSK database for server mode

2. Add setsockopt handler in net/tquic/tquic_socket.c:
   - For server sockets: Store PSK identity -> PSK mapping
   - For client sockets: Store PSK identity to send in ClientHello
   - Validate identity length (1-64 bytes)
   - Store in struct tquic_sock

3. Modify net/tquic/tquic_handshake.c server path:
   - In `tquic_server_hello_psk()`, extract PSK identity from ClientHello
   - Call `tquic_client_lookup_by_psk()` to find matching client config
   - If found: Check rate limit with `tquic_client_rate_limit_check()`
   - If rate limit exceeded: Reject with EQUIC_CONNECTION_REFUSED, log "rate limited"
   - If rate check passes: Accept and bind client to connection
   - If PSK not found: Reject with EQUIC_CONNECTION_REFUSED
   - Log PSK identity for debugging (ratelimited)

4. Add server PSK callback:
   - `tquic_server_psk_callback()` for TLS layer
   - Returns PSK if identity matches registered client
   - Returns NULL (reject) if unknown identity

Per CONTEXT.md: No 0-RTT, always full handshake for security.
Per CONTEXT.md: Connection rate limiting per client prevents abuse.
