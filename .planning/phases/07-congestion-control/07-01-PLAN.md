  <name>Task 1: Create CC framework central registry</name>
  <files>

  <action>
Create the central CC registry in net/tquic/cong/tquic_cong.c:

1. Define static list and spinlock for CC algorithm registration:
   ```c
   static DEFINE_SPINLOCK(tquic_cong_list_lock);
   static LIST_HEAD(tquic_cong_list);
   ```

2. Implement tquic_register_cong() and tquic_unregister_cong():
   - Register adds to list (already declared in tquic.h)
   - Unregister removes from list
   - Both use spinlock for thread safety

3. Implement tquic_cong_find(const char *name):
   - RCU-protected lookup by name
   - Returns tquic_cong_ops* or NULL
   - Used by sysctl and path creation

4. Implement tquic_cong_init_path(struct tquic_path *path, const char *name):
   - Find CC ops by name (or use default "cubic")
   - Call ops->init(path) to create per-path state
   - Store ops pointer in path structure for callback dispatch
   - Return 0 on success, -errno on failure

5. Implement tquic_cong_release_path(struct tquic_path *path):
   - Call ops->release(path->cong) if path has CC state
   - Clear path->cong and ops pointer
   - Safe to call with NULL state

6. Implement tquic_cong_on_ack(path, bytes_acked, rtt_us) dispatch:
   - Calls path's CC ops->on_ack if registered
   - Updates path->stats.cwnd from CC

7. Implement tquic_cong_on_loss(path, bytes_lost) dispatch:
   - Calls path's CC ops->on_loss if registered

8. Implement tquic_cong_on_rtt(path, rtt_us) dispatch:
   - Calls path's CC ops->on_rtt_update if registered

Create header net/tquic/cong/tquic_cong.h with:
- tquic_cong_find() declaration
- tquic_cong_init_path() declaration
- tquic_cong_release_path() declaration
- tquic_cong_on_ack/loss/rtt dispatch declarations

Add CC ops pointer field to struct tquic_path in include/net/tquic.h if not present:
```c
struct tquic_cong_ops *cong_ops;  /* Current CC algorithm ops */
```

1. Update net/tquic/Makefile to build the CC framework:
   Add to tquic-y:
   ```makefile
   tquic-y += cong/tquic_cong.o
   ```
   This ensures the CC framework is part of the main tquic module.

2. Update Kconfig to add CONFIG_TQUIC_CONG option (default y when TQUIC enabled):
   ```kconfig
   config TQUIC_CONG
       bool "TQUIC Congestion Control Framework"
       depends on TQUIC
       default y
       help
         Congestion control framework for TQUIC multipath connections.
         Supports Cubic, BBR, COPA, Westwood, and coupled (OLIA/BALIA).
   ```

3. Wire CC init to path creation in net/tquic/pm/path_manager.c:
   - In tquic_path_add() or wherever paths are created
   - After path struct is allocated and initialized:
     ```c
     #include "../cong/tquic_cong.h"

     ret = tquic_cong_init_path(path, NULL);  /* NULL = use default */
     if (ret) {
         pr_warn("tquic: failed to init CC for path %u: %d\n",
                 path->path_id, ret);
         /* Continue without CC - not fatal */
     }
     ```

4. Wire CC release to path removal:
   - In tquic_path_remove() or path cleanup
   - Before path struct is freed:
     ```c
     tquic_cong_release_path(path);
     ```

5. Wire CC callbacks to packet processing in net/tquic/tquic_input.c:
   - When ACK is processed and RTT is measured:
     ```c
     tquic_cong_on_ack(path, bytes_acked, rtt_us);
     tquic_cong_on_rtt(path, rtt_us);
     ```
   - When loss is detected:
     ```c
     tquic_cong_on_loss(path, bytes_lost);
     ```
   - Find the ACK processing function (likely in handle_ack_frame or similar)
   - Find the loss detection function

6. Ensure struct tquic_path has both cong (state) and cong_ops (ops) fields.
